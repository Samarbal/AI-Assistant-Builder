# ADR-002: Authentication and Authorization

Status: accepted

## Context

The MVP requires simple owner authentication and strict isolation between each business owner's assistants and associated data. Authentication must remain distinct from persistence while integrating with Supabase and FastAPI.

## Decision

- Use Supabase Auth for registration, login, and logout.
- Keep the MVP authentication scope limited to those flows and authenticated owner isolation.
- FastAPI validates the authenticated Supabase user for protected operations.
- FastAPI derives the owner identity from the validated Supabase session and applies owner-scoped service operations.
- Use Supabase Row Level Security as a database-level owner-isolation boundary in addition to FastAPI checks.
- Keep Supabase Storage private; authenticated owner file access uses short-lived signed URLs only when needed.

## Alternatives considered

- Custom application-managed password and session authentication: rejected because Supabase Auth is the approved MVP choice.
- FastAPI checks without RLS: rejected because one application-layer boundary is insufficient for the approved isolation decision.
- RLS without FastAPI owner checks: rejected because domain operations still need explicit owner scoping and safe authorization behavior.

## Rationale

Supabase Auth minimizes custom credential handling while FastAPI remains the application authorization boundary. RLS provides defense in depth for owner data, and private storage prevents public access to uploaded knowledge files.

## Consequences

- Protected owner APIs require a valid Supabase-authenticated identity.
- Every assistant, file, conversation, draft, and published snapshot operation is owner-scoped.
- Public widget requests do not receive owner credentials or draft access.
- Auth and storage policies require coordinated testing with FastAPI behavior.

## Risks / limitations

- Session transport and token validation must be configured consistently between the client, FastAPI, and Supabase.
- Service-role credentials, if used for trusted processing, bypass RLS and must never be exposed to public requests.
- Password recovery, email verification, social login, roles, and teams are outside the MVP.
